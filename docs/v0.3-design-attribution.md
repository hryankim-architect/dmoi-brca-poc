# DMOI v0.3 Design, Per-patient SHAP/IG attribution

**Status:** Design draft. Implementation next.

## Why attribution matters

v0.1 + v0.2 established that DMOI generalizes (TCGA test 0.968, METABRIC
0.909), but the model is still a black box at the per-patient level. A
clinical-decision-support narrative requires: "for THIS patient,
HERE are the genes that pushed the prediction toward LumB." Without
attribution, the disagreement signal is a number; with attribution, it's
explainable.

## Library choice

[Captum](https://captum.ai/), Meta's PyTorch-native interpretation
library. MIT licensed, ~5 MB install. Provides Integrated Gradients,
DeepLIFT, GradientSHAP, and LayerGradCam in a single API consistent with
PyTorch's autograd.

Add to `pyproject.toml` deps: `captum>=0.7.0`.

## Algorithm choice

**Integrated Gradients (IG)** from Sundararajan et al. 2017. For a
trained model `f` and input `x` with reference baseline `x'`, IG
attributes each input dimension `i` by:

```
IG_i(x) = (x_i - x'_i) * integral_{alpha=0..1} (df/dx_i)(x' + alpha*(x - x')) d_alpha
```

Approximated by Riemann sum (50 steps by default). Satisfies the
completeness axiom: `sum_i IG_i(x) = f(x) - f(x')`.

Why IG over alternatives:
- Vanilla gradient × input: noisy, no completeness guarantee.
- DeepSHAP: slower, requires bigger background distribution.
- LayerGradCam: better for spatial models (CNNs), not the right fit for tabular.

## Attribution targets

Per patient, three separate IG runs producing three attribution maps:

1. **`final_logit`**, the model's primary output (post-fusion + classifier head).
   The clinical headline: which genes pushed THIS patient toward LumB?
2. **`lumA_pole`**, `s_LumA`, the LumA-pole sub-classifier score.
   Architecture-level explanation: why did the LumA-pole branch produce its score?
3. **`lumB_pole`**, `s_LumB`, the LumB-pole sub-classifier score.
   Architecture-level explanation: why did the LumB-pole branch produce its score?

Three attribution maps × n_test patients × (RNA + meth) modalities =
6 × n_test 2D arrays. For TCGA test (n=84) this is 6 × 84 = 504
per-patient attribution vectors; for METABRIC (n=1175) it's 7,050.
Captum runs the 50-step IG approximation in ~0.5s per patient on MPS,
so total runtime is ~1 min for TCGA test, ~7 min for METABRIC. We'll
ship TCGA test attribution in v0.3 and consider METABRIC v0.4.

## Baseline choice

**Zero tensor** in the standardized domain. Because the train
StandardScaler centers each feature at zero, a zero input corresponds
to the train per-feature mean. Standard choice from the IG literature,
clean interpretation: "compared to an average TCGA train patient."

## Output structure

### Per-patient table (CSV)

`audit/dmoi_explain_per_patient.tsv`, one row per (sample_id, target,
top-k rank), columns:

| col | meaning |
|---|---|
| sample_id | patient ID |
| target | "final_logit" / "lumA_pole" / "lumB_pole" |
| modality | "rna" / "meth" |
| rank | 1..10 (top-K by absolute attribution) |
| feature | gene symbol or HM450 probe ID |
| attribution | signed IG value |
| input_value | standardized input value the patient had for this feature |

### Global aggregate (TSV + plot)

`audit/dmoi_explain_global.tsv`, mean |attribution| per
(target, modality, feature), ranked. Top-50 per target × modality
combination → 300 rows.

Quick matplotlib plot: top-20 bar chart per target. PNGs saved to
`audit/dmoi_explain_global_{target}.png`.

### Headline audit MD

`audit/dmoi_explain_v0.3.md`, summary tables, completeness-axiom
check (sum of IG ≈ f(x) - f(0) within numerical tolerance),
example patient deep-dives (3 patients: one confident-LumB, one
confident-LumA, one borderline disagreement).

## Limitations for v0.3

In:
- TCGA test set (n=84), single trained model from `eval_dmoi.py`'s final pass
- Three targets × two modalities × per-patient + global aggregates
- Completeness check + visualization

Out (deferred):
- METABRIC attribution (compute cost moderate; ship in v0.4 if useful)
- Cell-level attribution on hnscc-time pipeline (different repo)
- Counterfactual explanation ("what would have to change to flip the prediction"), adversarial-style, much heavier
- Pathway aggregation (e.g., MSigDB), useful but adds dependency

## Test plan

`tests/test_attribution.py`:
1. **Shape**: output arrays match expected (n_samples, n_features).
2. **Completeness**: `sum_i IG_i(x) ≈ f(x) - f(0)` within 1e-3.
3. **Determinism**: same input twice → same attribution (within float tolerance).
4. **Direction sanity**: synthetic 2-feature model where feature 0 strongly drives the output, IG attribution puts positive mass on feature 0.
5. **Baseline invariance**: zeros baseline produces same attribution as `baselines=None` (Captum default zero).
6. **Modality separation**: rna and meth attribution arrays have the right shapes and are not entangled.
