# v0.7 design — pathway-level attention (architecture-level extension)

## Status

Design phase. Four variants compared. User-pick → implementation → smoke.

## Context

v0.5 + v0.6 showed that per-gene Integrated Gradients, when rolled up
to MSigDB Hallmark pathways, recovers the architectural prior: the
LumA pole loads `ESTROGEN_RESPONSE_EARLY/LATE` ~300× harder than
cell-cycle pathways; the LumB pole loads `E2F_TARGETS /
G2M_CHECKPOINT / MYC_TARGETS_V1` ~45× harder than ER pathways. Both
findings hold on TCGA test (n=84) and METABRIC (n=1,175), and survive
the 50-set Hallmark widening on both cohorts.

This is a v0.5/v0.6-level interpretability win, but it lives entirely
**post-hoc**. The model itself sees genes, attends to genes, and
fuses gene-level latents. The pathway story is reconstructed after
training by summing IG attributions.

v0.7 asks: *what if the architecture treats pathway programs as
first-class signals during training, not only at interpretation time?*

## Current architecture (v0.6 recap)

```
x_rna (20,530-dim)  ─┐
                     ├─ for each pole P ∈ {LumA, LumB}:
x_meth (10,000-dim) ─┤   1. PoleAttention(rna_mask_P) ⊙ x_rna  → masked input
                     │      (rna_mask_P is fixed 0/1 from priors.HALLMARK_SETS,
                     │       e.g. LumA mask = union of ER_EARLY/LATE genes
                     │       intersected with feature space)
                     │   2. PoleAttention(meth_mask_P) ⊙ x_meth → masked input
                     │      (cis-mapped from gene mask via HM450 probemap)
                     │   3. RNAEncoder(masked rna) → z_rna_P     (128-dim)
                     │   4. MethEncoder(masked meth) → z_meth_P   (128-dim)
                     │   5. PoleFuser(z_rna_P, z_meth_P) → z_fused_P (64), s_pole_P
                     │
                     ├─ disagreement = |s_LumA − (1 − s_LumB)|  (scalar)
                     └─ ClassifierHead([z_LumA, z_LumB, disagreement]) → logit
```

The "hypothesis attention" is a **fixed binary mask** derived from the
priors. Pathway identity exists in the data preparation step, not in
the trainable parameters.

## Variants

### Variant A — Pathway-projected input (replace genes with pathway scores)

```
x_rna (20,530) ─→ pathway_project(...) ─→ x_path (50)  ─→ ... rest of model
```

Where `pathway_project` = mean expression of each Hallmark pathway's
genes (or a learned linear projection). Discards individual gene
identity entirely.

- **Pros**: Tightest, cleanest architecture. If AUROC holds, that
  proves pathway-level info is sufficient — a strong scientific
  claim. Model size shrinks dramatically (50-dim input vs 20,530).
- **Cons**: AUROC almost certain to drop noticeably (~0.95 → ~0.90?
  hypothesis). Loses gene-level interpretability — can no longer
  reproduce v0.3/v0.4 per-gene IG. Probably gets dominated by the
  baseline LogReg-on-genes 0.963 ceiling.
- **Honest assessment**: probably an interesting *ablation*, not the
  v0.7 headline. Worth running as a control.

### Variant B — Pathway-augmented input (concat genes + pathway scores)

```
x_rna_aug = concat(x_rna (20,530), x_pathway_score (50))  → RNAEncoder
```

Pathway scores remain available alongside raw genes. The model can
learn to use either. Pole masks extended to cover pathway-score
features (each pole's mask covers its prior pathways + their member
genes).

- **Pros**: Information-preserving. AUROC should hold or slightly
  improve. Easiest to implement (small input-dim change). Pathway
  features show up explicitly in attribution analyses.
- **Cons**: Pathway scores are linear combinations of input genes —
  the encoder could learn this itself. Marginal architectural win.
  May not move the AUROC needle either way.
- **Honest assessment**: low-risk, modest expected return. Good
  step but doesn't really "treat pathways as first-class."

### Variant C — Parallel pathway encoder + cross-attention

```
x_rna ─→ RNAEncoder        ─→ z_gene (128) ─┐
                                              ├─ CrossAttn → z_fused (128)
x_pathway_score ─→ PathwayEncoder ─→ z_path (128) ─┘
```

Two parallel encoders, then a cross-attention layer that lets gene
and pathway representations attend to each other. Pole-specific
versions of each branch.

- **Pros**: True architectural separation. Gene and pathway are
  genuinely first-class. Cross-attention can encode "which pathway
  contexts help me read this gene's signal" and vice versa. Most
  expressive variant.
- **Cons**: Most complex. Adds ~50K parameters. Risk of overfit
  (n_train = 333). Cross-attention is fiddly to get right; the
  baseline DMOI architecture is already at the edge of the data's
  capacity.
- **Honest assessment**: highest ceiling, highest variance. Right
  variant if we want to commit a multi-day architecture experiment
  with full ablation table.

### Variant D — Learned pathway-pole alignment (the v0.6 finding made trainable)

The v0.6 finding ("LumA pole loads ER ~300× harder, LumB loads
cell-cycle ~45× harder") is currently *hardcoded* into the pole
masks. v0.7 D replaces the hardcoded mask with a **learned soft
attention over all 50 Hallmark pathways**.

```
pathway_score ∈ R^50  (per patient, per Hallmark pathway, derived from x_rna)
pole_pathway_attn ∈ R^{2 × 50}  (LEARNABLE — softmax over the 50 axis)
                                 ("LumA's mixture over pathways", "LumB's mixture")
pole_pathway_feature ∈ R^{2 × 1}   (per pole: weighted sum of pathway scores)

# The gene-level branch keeps the current pole_masks (now coarser, optional)
# The pathway-level branch is the new addition.
```

The pole-specific pathway attention is the analog of v0.6's
hand-picked mask, but learned. After training, `pole_pathway_attn`
itself is an interpretation artifact — we can ask: "does the model
discover that LumA = ER pathways and LumB = cell-cycle pathways?"

- **Pros**: Most principled extension of the v0.6 finding. The
  hypothesis "pathway program is the right inductive bias" becomes a
  *learned* claim, not an architectural assumption. Interpretability:
  the learned attention weights reproduce (or refute) the v0.6
  pathway ranking. Modest parameter add (~50-200 params for the
  attention matrix).
- **Cons**: If the model learns a different pole mixture than the
  v0.6 hand-pick, we have to decide whether that's a feature
  ("model discovered subtler biology") or a bug ("model overfit to
  333 patients"). Risk that the gene-level branch dominates and the
  pathway branch is ignored.
- **Honest assessment**: most elegant variant, clean story
  ("v0.6 found it post-hoc; v0.7 lets the model find it from
  scratch"), tractable in a 2-3 day sprint.

## Recommendation

**Variant D** is the cleanest narrative arc with the lowest
implementation risk. Variant B is a sensible fallback if D's learned
attention degenerates. Variant C is the most ambitious and probably
the right v0.8 candidate.

A **D + B-lite combo** is feasible:

1. Compute 50-dim `pathway_score` from `x_rna` as a deterministic
   pre-processing step.
2. Add a `PathwayPoleAttention` module with a learnable
   `(n_poles × n_pathways)` weight matrix, softmax-normalized per
   pole.
3. The pole's pathway-attention output becomes an extra latent
   feature fed into the existing fuser.
4. Keep the current gene-level `PoleAttention` unchanged (so the
   gene-level interpretability story is preserved).

Net effect: model gets an explicit "this pole pays this much
attention to this pathway" trainable signal. After training, the
attention matrix is itself the interpretability artifact.

## Success criteria

| Outcome | Read |
|---|---|
| AUROC holds (within ±0.005 of v0.6's 0.968) | Pathway attention adds nothing over the existing pole masks → "v0.6's hardcoded prior was already optimal" — still a publishable interpretability finding. |
| AUROC lifts (>0.973) | Pathway attention captures signal the gene-level masks missed. v0.7 is the architecture win we've been hunting since v0.0. |
| AUROC drops (<0.963) | Pathway branch is hurting more than helping; gene-level was already the right level. Honest negative; revert architecture, keep design doc as a recorded experiment. |
| Learned `pole_pathway_attn` matches v0.6 pathway ranking | Strongest interpretability outcome: same biology emerges from scratch. |
| Learned attention diverges sharply from v0.6 | Either (a) the model found a refinement, or (b) the model is overfitting. Inspect the divergent pathways carefully. |

## Out of scope for v0.7

- Methylation-side pathway attention (HM450 probes are not gene
  symbols; needs a probe → gene crosswalk and probe → pathway
  rollup pipeline; deferred to v0.8+).
- Multi-task pathway prediction (predicting per-pathway expression
  as a side task during training).
- Hierarchical pathway organization (Reactome's nested pathway
  taxonomy; would require C2 collection).
- AUROC hyperparameter sweep — the v0.6 hyperparameters carry over.

## Honest scope

- v0.7 is an architecture experiment. The honest outcome may be an
  *AUROC-neutral* finding that ships as "no, the hardcoded
  hypothesis-attention prior was already the right inductive bias,
  here's the evidence." That's still a v0.7-worthy release.
- v0.6 demonstrated that 50-set rollup confirms the prior on the
  v0.4-trained model. v0.7 may show the prior is already saturated
  at the input-mask level. That's information.
- Implementation will reuse `dmoi_brca.hallmark.load_hallmark_gmt`
  for the catalog and `dmoi_brca.pathway.pathway_aggregate` for
  per-patient pathway-score computation.
